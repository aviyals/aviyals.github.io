Git / Team workflow

Branching strategy.

Keep branches short-lived, focused, and easy to review.

Recommended approach

Simple team habits

Feature branches

Create one branch for each feature or fix, then open a focused pull request.

Protected main branch

Keep shared branches stable by requiring reviews and passing checks before merging.

Small pull requests

Keep changes easy to understand, test, review, and safely roll back.

Delete merged branches

Remove finished branches so the repository stays easy to navigate.
